# Decisions

Defaults picked while building, per brief Section 22. Newest last. Change any of these by editing the code and adding a new row.

| Date | Decision | Reason |
|---|---|---|
| 2026-10-02 | Backend is Supabase, one project per country per environment; India projects in `ap-south-1` (Mumbai). Firebase only for FCM, Crashlytics, Analytics, Remote Config, App Check. | Owner's choice (brief Section 5). |
| 2026-10-02 | Placeholder web domains `iwantusa.app` and `iwantindia.app`. | Real domains not bought yet. Change `webDomain` in `lib/country/*/`, the Android `deepLinkHost` in `android/app/build.gradle.kts`, `tool/ios/setup_flavors.rb`, and the sites' env vars. |
| 2026-10-02 | Package / bundle ids `com.calecute.iwant.usa` and `com.calecute.iwant.india`, with `.dev` and `.stg` suffixes for non-prod. | One reverse-DNS root for both legal entities; suffixes let all flavors install side by side. |
| 2026-10-02 | India accent colour `#C2410C` instead of the brief's `#E8590C`. | `#E8590C` fails WCAG AA contrast for white text on buttons. |
| 2026-10-02 | Minimum age 18 in both apps. | Contracts with sellers and payments; simplest compliant default in both countries. |
| 2026-10-02 | Analytics consent: opt-in in India (DPDP Act), opt-out in the USA. | Per the legal pack in `legal/`. |
| 2026-10-02 | GST slabs offered in the quote form: 0, 5, 18, 40 percent (default 18). | GST 2.0 rate structure from September 2025. |
| 2026-10-02 | All tax maths in integers with half-up rounding (GST in basis points, US sales tax in parts per million, see below); intra-state GST splits into CGST + SGST each rounded separately, inter-state uses IGST. US sales tax is entered by the seller and applies to the subtotal; delivery is untaxed. | Brief Section 20.1 (no floating point money). |
| 2026-10-02 | Demo mode: when `SUPABASE_URL` is empty the app runs on an in-memory marketplace (OTP `123456`, simulated sellers quote automatically). | Lets every flavor run and be tested before any account exists. |
| 2026-10-02 | Store product ids `seller_pro_monthly`, `seller_pro_annual`, `credits_10`, `credits_50`. | Same ids in both stores and both apps. |
| 2026-10-02 | Test OTP numbers: USA `+1 555-0100` to `+1 555-0103`, India `+91 0000000001` to `+91 0000000004`, code `123456`, configured only in `supabase/config.toml` and the hosted dashboard. | Section 23 addendum (fictional numbers, never in `seed.sql`). |
| 2026-10-02 | Edge Functions use a `deno.json` import map; no `package.json` under `supabase/functions`. | Section 23 addendum. |
| 2026-10-02 | Offline cache: one drift schema, one database file per flavor (`iwant_<country>_<env>.sqlite`). | Section 23 addendum. |
| 2026-10-02 | Dart formatter page width 120. | Matches the code style used throughout; enforced in CI. |
| 2026-10-02 | iOS flavors are generated by `tool/ios/setup_flavors.rb` (xcodeproj gem) instead of hand-editing the project. | Reproducible and idempotent; re-run after adding a flavor. |
| 2026-10-02 | Nightly store builds use a minutes-since-epoch build number written at build time, not committed. | Keeps nightly uploads monotonic without bump commits; release tags still use the `bump` lane. |
| 2026-10-02 | Store and Supabase deploy jobs skip with a warning when their secrets are missing. | Accounts are not linked yet; CI stays green meanwhile. |
| 2026-10-02 | Credit pack product ids are `credits_10` and `credits_50` (backend naming). | One id across Play, App Store, Stripe and Razorpay. |
| 2026-10-02 | Cold email sequences to businesses run automatically (Section 21.2) but every campaign starts paused; only campaigns an admin sets to active are sent, with warm-up, caps and bounce/complaint brakes. Panel sends are one lead at a time after review. | Matches the brief while keeping a human switch before anything leaves the system. |
| 2026-10-02 | India brochures are English only for now. | The Dart `pdf` package can't shape Devanagari; Hindi brochures need an Edge Function renderer or pre-made templates. |
| 2026-10-02 | US sales tax rates are integer parts per million (ppm): 8.875 % (NYC) = 88750, tax = round_half_up(subtotal × ppm, 1000000). The seller types up to 3 decimals in percent. India GST stays in basis points. The server still accepts `p_sales_tax_rate_bp` from older app versions (ppm = bp × 100) and keeps a rounded `rate_bp` next to `rate_ppm` in `tax_breakdown` for them; readers prefer `rate_ppm` and read legacy rows as `rate_bp × 100`. | Basis points cannot express 8.875 %. Changed in one step in SQL (migration 1050), TypeScript, Dart and the shared fixtures. |
| 2026-10-02 | Admin panel UI is English only. | Internal tool; brochures themselves are per language. |
| 2026-10-02 | India web payments stay behind the monetization switch: the India project keeps `monetization_enabled=false` (free for every seller) until a gateway is approved. Admins can record a UPI or bank transfer against a seller plan by hand (`admin_grant_entitlement`, audit-logged). | Razorpay KYC is blocked and BillDesk was rejected (owner update). |
| 2026-10-02 | Android in-app seller subscriptions and credit packs use Google Play Billing; iOS uses StoreKit; Stripe web checkout is for the USA web only. | Store rules for digital goods; Stripe US is approved. |
