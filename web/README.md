# Websites (Vercel)

Three Vercel projects, all on the free Hobby plan while building and testing. Hobby is for **non-commercial use only**: move a site to Vercel Pro (or Cloudflare Pages, Netlify or a VPS; the output is plain static files) before it takes payments or shows ads.

| Folder | Vercel projects | What it is |
|---|---|---|
| `app_site/` | `iwant-usa-web`, `iwant-india-web` (same folder, `SITE_COUNTRY` differs) | Landing page, legal pages, account deletion, deep-link fallbacks, `.well-known` files, seller signup / contact / waitlist forms, SEO price pages, buying guides |
| `trends_site/` | `trends-web` | Separate trends news site (Section 21.10), own domain, no app branding |
| `content/legal/` | none | Generated by `python3 legal/build.py`; read by `app_site` at build time. Do not edit by hand |
| `shared/ai_bots.json` | none | AI crawler list used by every site's `robots.txt` |

## Project settings (all three)

- **Framework preset:** Astro. **Install:** `npm ci`. **Build:** `npm run build`. **Output:** `dist` (already set in each `vercel.json`).
- **Root directory:** `web/app_site` or `web/trends_site`.
- **Include files outside the root directory in the build step: ON.** `app_site` reads `web/content/legal`, `web/shared` and `branding/`; `trends_site` reads `web/shared`.
- **Node.js:** 22.x. Production branch `main`; every other branch gets a preview deployment.
- **Spend management:** set a spend limit and usage alerts (Settings > Billing) so a traffic spike cannot create a bill.
- **Firewall:** turn on Bot Protection and the AI-bot rule (enforces `robots.txt`), and rate-limit form-heavy paths (e.g. 10 requests per minute per IP on `/sellers`, `/contact`, `/waitlist`, `/legal/account-deletion`).
- **Domains:** keep DNS at the registrar. `iwantusa.app` and `iwantindia.app` are placeholders, and so is the trends domain.

## Environment variables

None of these are secrets. They all end up in public HTML or `/.well-known` files. The Turnstile **secret** key belongs only in the Supabase Edge Function's secrets, never here. Every variable is listed in each folder's `.env.example`.

### `app_site`: set per project

| Variable | `iwant-usa-web` | `iwant-india-web` |
|---|---|---|
| `SITE_COUNTRY` (required) | `usa` | `india` |
| `SITE_URL` | `https://iwantusa.app` | `https://iwantindia.app` |
| `ANDROID_SHA256_FINGERPRINTS` | Play App Signing + upload key SHA-256, comma-separated | same, for the India app |
| `ANDROID_EXTRA_PACKAGES` | optional, e.g. `com.calecute.iwant.usa.stg` | optional |
| `APPLE_TEAM_ID` | 10-character team id | same |
| `APPLE_APP_ID` | numeric App Store id once live (turns on store badge + Smart App Banner) | same |
| `PLAY_STORE_LIVE` | `1` once the listing is public | same |
| `PUBLIC_TURNSTILE_SITE_KEY` | Turnstile site key for the domain | same |
| `FORMS_ENDPOINT` | `https://<usa-prod-ref>.supabase.co/functions/v1/web-forms` | `https://<india-prod-ref>.supabase.co/functions/v1/web-forms` |
| `SUPPORT_EMAIL` | optional fallback shown when forms are off | same |
| `SEO_DATA_URL` | `https://<usa-prod-ref>.supabase.co/storage/v1/object/public/public-data/seo/usa.json` (nightly SEO export) | `https://<india-prod-ref>.supabase.co/storage/v1/object/public/public-data/seo/india.json` |
| `SEO_DATA_REQUIRED` | `1` on Production only (a failed fetch fails the build, so the last good deployment stays live instead of a build without price pages) | same |
| `LEGAL_STRICT` | `1` on Production only (fails while legal placeholders remain) | same |

If a value is unset, the build still succeeds: `assetlinks.json` and `apple-app-site-association` get `REPLACE_WITH_...` placeholders (links will not verify), forms render disabled, and store badges say "Coming soon" and link to `/waitlist`. Each case prints a build warning.

### `trends_site`

`SITE_URL`, `SITE_NAME`, `EDITOR_NAME`, `EDITOR_EMAIL`, `PUBLIC_TURNSTILE_SITE_KEY`, `FORMS_ENDPOINT`, `TRENDS_DATA_URL` (below), and `NEWS_SITEMAP=1` only once the site qualifies for Google News. Publishing caps, the ramp level and the kill switch live in `trends_site/data/config.json`, which the admin panel owns.

`TRENDS_DATA_URL` is the trends pipeline's public bucket, e.g. `https://<ref>.supabase.co/storage/v1/object/public/trends-public/` (or its `index.json`). When it is set, `npm run build` first runs `scripts/fetch-trends-data.mjs` (the `prebuild` step), which downloads `index.json` and every `articles/<slug>.json` it lists into `.trends-remote/` (gitignored); the build then reads those **in addition to** `data/articles/` (local files win on duplicate slugs) and runs every gate below on them, unchanged. The remote index can only tighten `config.json`: its kill switch pauses publishing from its `paused_at`, and its daily cap per country applies only when lower (so `config.json` caps act as a ceiling; raise them in the repo when the admin ramps up). The build fails if the URL is not https or the index cannot be loaded or is malformed, so a broken bucket never publishes an empty site; single unreadable articles are skipped with a warning. Unset, only `data/articles/` is built.

## Local builds

```sh
cd web/app_site && npm ci
npm run build:usa        # or build:india; other variables: export them first (e.g. set -a; . ./.env; set +a)
SEO_DATA_FILE=data/seo/fixtures/usa.json npm run build:usa   # exercise the price-page gates with sample data

cd ../trends_site && npm ci
npm run build                                   # real articles from data/articles (empty by default)
BUILD_NOW=2026-10-02T00:00:00Z npm run build:fixtures   # sample articles, one per gate
TRENDS_DATA_URL=https://<ref>.supabase.co/storage/v1/object/public/trends-public/ npm run build   # plus the pipeline's bucket
```

Each build logs what it published and why everything else was skipped or set to noindex.

## How content gets in (and stays clean)

- **Legal pages:** edit `legal/<country>/*.md` and `legal/config.json`, run `python3 legal/build.py`, and commit. The site fills in the web-domain placeholder from `SITE_URL`.
- **SEO price pages and buying guides (`app_site`, Section 21.9):** every night at 02:40 UTC `pg_cron` calls the Supabase Edge Function `seo-export` (job `iwant-seo-export`). It runs `public.seo_export()` (aggregated, anonymised stats only: medians and quartiles over at least the threshold number of quotes and sellers, rounded; most-quoted models only when several sellers quoted them; no buyer data, no seller's own quote), checks the JSON again, uploads it to the public Storage bucket `public-data` as `seo/<country>.json` and POSTs the Vercel **Deploy Hook** stored in the function secret `VERCEL_DEPLOY_HOOK_APP_SITE` (without it the function only logs a dry run). Point `SEO_DATA_URL` at that public object URL (table above); the loader adds a `?v=<minute>` cache-buster so the rebuild never reads the CDN's previous copy. Admins can also press **Run export now** in the admin panel (SEO pages screen). A city x category page is indexable only with at least 10 quotes from at least 3 sellers in 90 days and a quote within the last 90 days (defaults; admins edit them in the panel, and the export writes them into the data file). Rows below that are built with `noindex` and left out of the sitemap. Rows with no quotes, merged towns (their quotes count for the larger area page, which lists them), and restricted or blocked categories are not built at all. The committed default files have no page rows, so nothing is published until real data exists.
  - Buying guides (`/guides/<slug>`, Article schema, `sitemap-guides.xml`) come from the same file (`guides[]`). The export only contains guides a person approved in the admin panel: `approved` ones are built as `noindex` previews and linked from nowhere; `published` ones are indexable while their last review is under 184 days old (re-review twice a year). Guide pages show the reviewer date, an AI-assistance note when it applies, and the live median for their city x category. Markdown is rendered by `src/lib/markdown.ts` (no raw HTML).
  - `sellers[]` (directory entries for sellers who opted in) is exported too; the site does not build seller directory pages yet.
  - Data format: `SeoData` in `src/lib/seo.ts`; examples in `data/seo/fixtures/` (`SEO_DATA_FILE=data/seo/fixtures/usa.json npm run build:usa`).
- **Trends articles (`trends_site`, Section 21.10):** the pipeline (`supabase/functions/trends-*`, see `supabase/API.md` section 13) writes one JSON file per article to the `trends-public` bucket read through `TRENDS_DATA_URL` (articles may also be committed to `data/articles/`; see `data/fixtures/` for the format) and calls the project's Deploy Hook (`VERCEL_DEPLOY_HOOK_TRENDS_SITE`). The build rejects any article that fails the gates: at least 2 independent sources; sensitive topics only with a recorded human approval; originality (upstream check plus local n-gram overlap and long-quote checks); fact consistency; at least 250 words with a local angle and what to watch next; balanced, non-partisan perspectives; and the kill switch plus per-country daily and hourly caps. Superseded articles and articles whose traffic died after the trend ended are set to `noindex`.

## Form endpoint contract (Edge Function not in this folder)

Forms `POST` JSON to `FORMS_ENDPOINT`:

```json
{ "form": "seller_signup | contact | waitlist | account_deletion | trends_contact",
  "country": "usa | india", "page": "/sellers", "submitted_at": "ISO",
  "fields": { "...": "..." }, "consents": [{ "key": "consent_email", "text": "exact wording shown" }],
  "honeypot": "", "turnstile_token": "..." }
```

The function must do the following:

- Verify `turnstile_token` server-side with the Turnstile secret.
- Drop any request whose `honeypot` is not empty.
- Rate-limit per IP and answer `429` with `Retry-After` when the limit is hit.
- Allow CORS from the site's origin only.
- Store consent text and timestamps in `consents`.
- Run double opt-in for the waitlist; nothing is sent before the person confirms.
- Confirm account-deletion requests by OTP to the registered phone.

Buyer outreach stays consent-based: the forms only collect people who opt in themselves.

If the function is served from a custom domain instead of `*.supabase.co`, add that domain to `connect-src` in the CSP in `vercel.json`.
